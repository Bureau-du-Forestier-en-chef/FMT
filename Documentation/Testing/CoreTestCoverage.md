# Test Coverage of Core

> Generated by [CoreTestCoverage.cmake](CoreTestCoverage.cmake) from the headers of `Include/`, the
> GoogleTest cases of `Tests/` and the hand-written columns of
> [CoreTestCoverage.csv](CoreTestCoverage.csv). Do not edit this file: edit the CSV, or
> [CoreTestCoverage.md.in](CoreTestCoverage.md.in) for the text, then regenerate it.

This document is the inventory of the classes of namespace `Core` and of their tests, that
[issue #350](https://github.com/Bureau-du-Forestier-en-chef/FMT/issues/350) asks for. It guides the unit
tests of lots 7 and 8, and one of the conditions to close the issue is that it no longer shows a priority
class without a test.

- **What it covers.** Every class and struct defined in namespace `Core` by a header of `Include/`,
  templates and public nested classes included, with its priority, its tests at each level, its known
  issues, and the descriptive columns of #350.
- **What it does not cover.** The other namespaces (`Models`, `Parser`, `Graph`, `Spatial`,
  `Heuristics`...), even where #350 names one of their classes (`FMTGraphStats`, `FMTEvent`); the free
  functions and the enumerations of `Core` (`Include/FMTutility.h`); line coverage, which arrives with
  lot 9.
- **Where the work is tracked.** [Tests/ETAT.md](../../Tests/ETAT.md), in French, is the working file of
  the test campaign: its rules, the order of the lots (section 6.3), the known defects (section 2.7) and
  the gaps by criticality (section 3), from which the priorities below are taken. It points back here.

## Regenerating

```bash
cmake -P Documentation/Testing/CoreTestCoverage.cmake
```

The script needs no build and runs from any folder. It rewrites this document and the CSV, prints the
classes that appeared or disappeared, and lists them below. A new class gets an empty row in the CSV:
give it a priority there, then regenerate. Run it after adding a class to `Core` or a unit or integration
test.

| Column | Source |
| --- | --- |

| External dependencies, thread safety | Generated from the header and its source (ONNX Runtime, GDAL, R, Python, mutex), followed by the CSV |

## Priority

The priority comes from [Tests/ETAT.md](../../Tests/ETAT.md), and is not decided here:

1. **Priority 1**: a class that every model goes through, the chain of section 3.1 of the ETAT (reading,
   core objects, presolve, graph and matrix, results, writing), or a class in which a defect or a known
   behaviour of section 2.7 was found. Within priority 1, the classes with a defect come first, as
   section 6.3 orders the lots: they are those whose *Known issues* column names an issue.
2. **Priority 2**: a class used by the common flows of section 3.4 only (tasks, spatially explicit
   models, maps, non-spatial simulation, wrapper core).
3. **Priority 3**: a class used by the specialised functions of section 3.5 only (yield models,
   simulated annealing, operating areas, action transformations, predictors).

A helper type, such as a comparator or a hasher, takes the priority of the class it serves.

**System tests** lists a test of the public suite only if it checks a value that this class computes or
holds, as sections 2.2 and 3.1 of the ETAT describe them: a test that only ends without error does not
count. *None with a check* says that no such test was found.
